# 工具运行时名称对齐修复

## 问题

当前 agent 指令把宿主工具与插件工具混合描述，且错误日志显示模型尝试通过 Code Mode 的 `execute` 间接调用不存在的 `read`、`search`。这会在工具目录不含这些名称时产生 `Unknown tool`，并可能连续重试。

## 已批准方向

采用兼容层方向：修正 agent 工具契约、权限说明和回归测试；不注册 `read`、`search`、`execute` 同名插件别名，避免与宿主工具冲突。

## 范围

- 明确 `read`、`grep`、`glob`、`webfetch`、`websearch` 是宿主原生能力，只能按当前会话工具目录直接调用。
- 明确 `ast_grep_search`、任务工具和 CBM 工具是 Oceanus 注册能力。
- 将 `search` 统一为 `grep` 或对应 CBM 查询工具；禁止臆造 `search` 与通过不存在的 `execute` 代理调用工具。
- 保留现有工具注册和业务逻辑，不新增同名别名。
- 增加针对工具名称契约和错误回退的测试。

## 非目标

- 不修改当前工作区已有的无关未提交改动。
- 不实现 Code Mode 或动态工具代理。
- 不改变宿主 OpenCode 的原生工具注册。

## 验收

1. agent 提示词不再指导调用不存在的 `search` 或用 `execute` 代理 `read`/搜索工具。
2. 工具权限与提示词中的名称和插件实际注册集合一致，并保留必要的宿主工具声明。
3. 回归测试覆盖所有相关 agent，且现有测试、类型检查通过。
4. 不出现新的 `read/search/execute` 插件工具注册。

## Metis 分析

Metis 未调用：用户已确认单一低风险修复方向，未存在需要独立比较的未决方案。残余风险由回归测试和构建验证覆盖。
